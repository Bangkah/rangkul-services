The container health check route is `GET /healthz` and returns `{"status":"alive"}`.

## `POST /api/chat`

Request JSON:

```json
{
  "messages": [
    {"role": "user", "content": "Bagaimana cara mencari layanan kesehatan?"}
  ]
}
```

Response: streaming `application/x-ndjson` from the private Hugging Face Space. The Space's anti-diagnosis system prompt is static; client `system` messages and extra fields are rejected. RAG is currently disabled until a vector retriever is configured.

## `GET /api/facilities`

Response JSON: `{ "facilities": [...], "data_status": "demo" }`. Each item has `id`, `name`, `is_demo`, `address`, `schedule`, `timezone`, and `coordinates` (`latitude`, `longitude`). All current pins are synthetic placeholders; do not present them as real partner clinics.

## `POST /api/register-dummy`

Request JSON (plain text only; no KTP image upload):

```json
{"text": "Saya ingin simulasi pendaftaran."}
```

Response JSON: `{"registration_code":"RGKL-DEMO-0001","status":"confirmed","message":"..."}`. The static code is for UI demo only and does not create a real queue.

## `POST /api/community-guide`

Request JSON:

```json
{"text": "Masuk dari gerbang utama, lalu belok kiri."}
```

Response JSON includes generated `id`, submitted `text`, `status: "pending"`, and UTC `created_at`. The text is stored in SQLite.

## Errors and current limitations

Invalid payloads return FastAPI validation errors (422). Chat returns 503 when Hugging Face credentials are not configured, 502 for upstream failures, and 504 for upstream timeouts. Facilities are demo fixtures, RAG is not configured, and no staging endpoint is deployed.
